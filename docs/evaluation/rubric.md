# 평가 기준 (Rubric)

> 아이디어 카드의 `평가` 표를 채우는 기준. 해커톤 핵심 가치(실용성·디지털 포용·시민 체감)와 추진 목적(지속 가능한 공익 AI)에서 도출했다.
> **팀 내부 잠정 기준**: [공고·FAQ](../hackathon/announcement-faq.md)는 실용성·디지털 포용 UX·시민 체감 효과를 주요 평가 요소로 명시한다. 세부 배점은 미제공이다. 아래 6개 기준 균등·합계 30점은 공식 배점이 아니며, 공식 배점 확인 후 조정한다 (`work-plan.md` 미결정).

## 채점 원칙

- 점수마다 근거를 한 줄 이상 쓴다. 근거가 없으면 3점을 넘기지 않는다.
- 근거는 카드 본문·`brief.md`·`RES_XX` 안에 있어야 한다. 카드에 없는 장점을 채점 때 만들지 않는다.
- 같은 날 여러 카드를 채점하면 같은 기준으로 서로 비교해 점수를 맞춘다.

## 기준

### U 실용성 (Utility)

| 점수 | 기준 |
| --- | --- |
| 5 | 사용자가 첫 사용에서 바로 구체적 효용(돈·시간·위험 감소)을 얻는다 |
| 3 | 효용은 분명하지만 반복 사용이나 추가 입력이 있어야 나타난다 |
| 1 | 정보 제공 수준이거나, AI가 없어도 같은 효용을 낸다 |

### I 디지털 포용 (Inclusion)

| 점수 | 기준 |
| --- | --- |
| 5 | `문턱 낮은 인터페이스` 체크 5개 모두 근거 있음. 정보 약자가 도움 없이 끝까지 쓴다 |
| 3 | 체크 3~4개. 일부 단계에서 스마트폰 숙련이 필요하다 |
| 1 | 앱 설치·가입·긴 입력이 전제. 정보 약자가 대상이 아니거나 배제된다 |

### C 시민 체감 (Impact)

| 점수 | 기준 |
| --- | --- |
| 5 | Before/After 차이가 크고, 대상 규모가 근거로 제시된다 |
| 3 | 변화는 보이지만 대상이 좁거나 규모 근거가 약하다 |
| 1 | 변화가 추상적이다 ("편리해진다" 수준) |

### S 지속 가능성·연계

| 점수 | 기준 |
| --- | --- |
| 5 | 연계할 서울시 부서·기관·디지털배움터 현장과 운영 주체가 구체적이다 |
| 3 | 연계 방향은 있지만 운영 주체·방식이 불명확하다 |
| 1 | 해커톤 데모 이후 계획이 없다 |

### F 실현 가능성

| 점수 | 기준 |
| --- | --- |
| 5 | 핵심 기능 사전 코딩 없이 현장 6시간에 핵심 흐름 1개를 동작하는 MVP로 보일 수 있고, 필요한 데이터가 `확인됨` |
| 3 | 데모는 가능하지만 데이터 일부가 `미확인`이거나 목업에 기대야 한다 |
| 1 | 핵심 데이터·제휴가 없으면 데모가 불가능하다 |

### D 차별성

| 점수 | 기준 |
| --- | --- |
| 5 | 기존 공공·민간 서비스와 비교해 대상·채널·방식이 분명히 다르다 (비교 근거 있음) |
| 3 | 기존 서비스의 개선판이며 차이는 설명된다 |
| 1 | 기존 서비스와 사실상 같다, 또는 비교하지 않았다 |
