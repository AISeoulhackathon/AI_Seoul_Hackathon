# 팀원 이름을 기획 문서에 쓴다

| 필드 | 값 |
| --- | --- |
| 날짜 | 2026-11-04 |
| 결정자 | 사용자(팀원 강규민) |
| 관련 | [CLAUDE.md §4](../../CLAUDE.md#4-금지), [팀 명단](../planning/team.md), [2차 회의](../note/20261103-ideation-meeting-2.md) |

## 결정

사용자가 팀원 6명의 이름과 닉네임을 하네스에 적용하라고 요청했다. 이에 따라 **팀원 본인의 이름·닉네임**은 회의록·명단·역할 문서에 쓸 수 있다. 닉네임은 회의에서 화면에 보이는 표시 이름(예: 디스코드 표시명)이다. 연락처(전화·이메일·주소), 메신저의 숫자 계정 ID(받아쓰기에 이름 대신 찍히는 긴 숫자), 팀 밖 사람의 실명은 여전히 커밋하지 않는다.

## 배경

- 회의록이 참석자 A~E 같은 기호로만 남으면, 팀원이 하네스(챗봇)에 "누가 무엇을 맡았나"를 물어도 답할 수 없다.
- 저장소는 팀 내부용 private 저장소다. 해커톤 신청서와 제출 GitHub에도 팀원 구성이 드러난다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 참석자 기호 유지 | 역할·담당을 추적할 수 없어 회의록 용도가 약해짐 |
| 닉네임만 쓰기 | 사용자가 이름과 닉네임을 함께 적용하라고 요청함 |

## 영향

- CLAUDE.md §4 금지 항목에 이 결정의 예외를 명시한다. 하네스 검사 규칙은 바꾸지 않는다.
- 2차 회의록의 참석자 A~E를 이름으로 바꾼다. 1차 회의록의 참석자 1~4는 녹음 표기와 이름의 대응을 확인하지 못해 그대로 둔다.
- 저장소를 공개로 바꾸거나 제출용으로 외부에 공유하기 전에 이 결정을 다시 확인한다. 각 팀원에게 이름이 기록된다는 점을 알린다.
