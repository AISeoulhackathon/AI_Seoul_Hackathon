# IDEA_03: 마라톤 교통주의보

> 아이디어 출처: [1차 회의](../note/20261102-ideation-meeting-1.md), 2026-11-02 사용자 추가 제안. 문제의 실증 근거는 별도 조사 필요.
> 대회 제약: [사용자 제공 공고·FAQ](../hackathon/announcement-faq.md). 아래 범위는 제안이며 팀 확정 전 `draft`를 유지한다.

## 한 줄 요약

AI 리서치로 서울 마라톤의 일정·경로·시간을 수집하고, 사람이 확인한 통제 정보를 운전자·보행자에게 이동수단별 지도와 쉬운 말로 알려 준다. 공지 한 건의 AI 추출·사람 승인·지도 반영을 우선 구현 방향으로 채택하며 자동 수집·변경 감지·자동 우회는 후속 검토한다.

## 문제

- 문제 가설: 마라톤 통제를 미리 알지 못한 시민이 현장에서 이동을 중단하거나 돌아가는 불편을 겪는다. 회의에서 불만 글 사례가 언급됐으나 원문·발생 규모는 확인 필요.
- 근거: 자유 트랙 예시 '교통'([brief.md](../hackathon/brief.md)). 서울 마라톤 개최 빈도·통제 규모는 확인 필요.

## 대상 사용자

| 사용자 | 디지털 역량 | 지금은 어떻게 해결하나 |
| --- | --- | --- |
| 운전자 | 다양 | 지도 앱·교통 공지·현장 안내 이용 가설 (실제 이용 방식·통제 반영 범위 확인 필요) |
| 보행자 | 다양 | 지도 앱·현장 안내 이용 가설 (횡단 제한·대체 통행 정보 확보 여부 확인 필요) |

2026-11-02 사용자 의향에 따라 운전자와 보행자를 함께 대상으로 구체화한다. 팀의 아이디어 선정·MVP 범위 승인은 별도다.

| 대상 | 먼저 답할 질문 | 화면에 보여줄 정보 제안 |
| --- | --- | --- |
| 운전자 | 내가 이동할 시간에 어느 도로가 통제되는가? | 통제 도로·방향·시간, 공식 우회 안내가 있으면 함께 표시 |
| 보행자 | 이 길을 걷거나 도로를 건널 수 있는가? | 확인된 보행·횡단 제한과 시간, 공식 대체 통행 안내. 근거가 없으면 ‘보행 통행 여부 미확인’ |

차량 통제만 확인된 구간을 보행 금지로 표시하지 않는다. 지하도·육교 등은 개방·접근성 정보가 확인되지 않으면 이용 가능한 대안으로 단정하지 않는다.

## 해결 방식

- 사용자 의향(2026-11-02): 자동차·도보 각각에서 **주변 통제 보기**와 **목적지 경로 영향 확인**을 모두 제공한다. 세부 구현 범위와 자동 우회 포함 여부는 별도 검토한다.
- 주변 통제 보기: 이동수단·날짜·예정 시각 선택 → 현재 위치 또는 검색한 지역 주변의 통제 표시 → 구간별 시간·출처 확인. 위치 권한 없이도 지역 검색으로 이용하도록 설계한다.
- 목적지 경로 영향 확인: 이동수단·출발 예정 시각·출발지·목적지 입력 → 경로 조회 → 경로와 통제 구간이 겹치는 곳 및 시간 조건 표시. 자동차·도보 경로 좌표 확보와 공간 비교 가능성은 조사 필요다.
- 경로 영향 확인은 자동 우회 생성과 별개다. 일반 경로 조회 결과를 통제 회피 경로로 표현하지 않는다. 구간 통과 예상 시각을 계산하지 못하면 출발 시각만으로 영향을 배제하지 않고 시간 확인이 필요한 구간으로 표시한다.
- AI가 하는 일: 운영자가 입력한 공식 공지 한 건에서 대회명, 개최일, 경기 시간, 경로, 구간별 통제 시간·이동수단을 추출하고 원문 근거와 함께 제시한다. 누락·상충 값은 `확인 필요`로 남긴다. 좌표·시간 계산으로 확인한 경로 영향을 쉬운 말로 설명한다. 자동 검색·수집과 변경 감지는 후속 확장이다.
- 사람이 하는 일: 원문 근거와 추출값을 나란히 보며 수정·승인하고 지도 구간을 검수한다. 미승인 추출값은 확정 통제로 게시하지 않는다. **경기 시간과 통제 시간은 별도 필드**로 두고, 차량 통제를 보행·자전거 통제로 일반화하지 않는다.
- 사용자 흐름 제안: 이동수단(자동차/도보)·날짜·예정 시각·동네 선택 → 지도 주의 구간 확인 → 해당 구간의 시간·영향받는 이동수단·공식 안내 확인.
- 표시 원칙: 구간마다 출처 링크, 공지 시각(제공된 경우), 마지막 확인 시각, 검증 상태를 표시한다. 정보 없음은 통행 가능으로 표시하지 않는다.
- 지도 형태: 자체 웹 지도에서 주의 표시를 제공하는 안을 우선 검토한다. 기존 지도 앱 내부에 표시를 추가할 수 있는지는 지원 기능·약관 확인 전까지 미정이다.

## MVP 범위

- 사용자 희망 범위는 자동차/도보 × 주변 보기/목적지 경로 영향 확인이다. 아래 공통 정보 처리 흐름을 두 진입점이 함께 사용하도록 설계한다. 팀의 최종 MVP 승인은 별도다.
- 목적지 기능은 경로 좌표·통제 구간 비교·시간 조건 표현의 구현 가능성을 먼저 검증한다. 목적지만 지도에 표시하는 것을 경로 영향 확인 기능의 완성으로 간주하지 않는다.
- **채택한 자동화 방향** ([결정 기록](../decisions/20261102-marathon-ai-workflow.md)): 운영자가 공식 공지 1건 입력 → AI 정보 추출·근거 표시 → 사람 수정·승인 → 자동차/도보 모드별 지도 주의 표시·쉬운 말 상세 안내. 두 모드는 같은 대회 자료를 사용하되 통제 정보는 구분한다. 실제 사용 가능한 공지·지도 데이터 확보를 전제로 한다.
- 우선 가치: “이 구간을 이 시간에 이동할 때 주의하세요”를 출처와 함께 보여 주기. 자동 우회 탐색 없이도 이 흐름을 데모한다.
- 확장 후보: 공지 자동 검색·수집, 변경 감지, 원문에 명시된 우회 안내 제공, 기존 지도 길찾기 연결, 통제 구간을 회피하는 자동 경로 탐색. 세 방식의 기능·검증 부담을 구분해 논의한다.
- 제안 범위 밖: 전체 행사(축제·집회) 확장, 실시간 전 구간 감시, 자동 푸시 알림, 안전·통행 가능 보장.
- 사전 준비: 문제 정의·와이어프레임·데이터 조사·개발 계획까지만 준비하며, AI 추출·지도 경고·우회 등 핵심 기능 코드는 본선 당일 구현한다 ([공고·FAQ](../hackathon/announcement-faq.md)).
