# IDEA_10: 서울 퀘스트 보드 — 실무 과제로 쌓는 청년 첫 경력

> 출처: [회의 후 추가 메모](../note/20261102-quest-board.md). 트랙 ③ 청년 일자리가 주 트랙이고 ② 소상공인에도 걸친다.

## 한 줄 요약

기업·소상공인·공공기관의 실무 과제를 1~2주짜리 유료 퀘스트로 쪼개 청년이 수행하게 하고, 검증된 결과물을 경험치·포트폴리오로 쌓아 일정 레벨에 이르면 채용으로 잇는다.

## 문제

- 청년: 기업은 실무 경험을 요구하지만 첫 경력을 쌓을 기회가 없어 '쉬었음' 상태로 남는다.
- 소상공인: SNS 운영, 메뉴판 디자인, 데이터 정리, 웹페이지 같은 일을 직접 할 역량이나 외주 비용이 부족하다.
- 근거: '쉬었음' 청년(15~29세) 전국 40만 명 이상, 그중 34.1%가 직무·조건 미스매칭으로 쉼. 기업은 인재난, 청년은 구직난인 역량-요구 격차([brief.md](../hackathon/brief.md) 트랙 ③). 소상공인 대다수가 경영 데이터 분석 수단이 없음([brief.md](../hackathon/brief.md) 트랙 ②).

## 대상 사용자

| 사용자 | 디지털 역량 | 지금은 어떻게 해결하나 |
| --- | --- | --- |
| '쉬었음'·첫 경력 청년 | 높음 | 인턴·공모전·개인 프로젝트 (확인 필요) |
| 소상공인 | 낮음~중간 | 직접 하거나 외주, 또는 포기 |
| 기업·스타트업·공공기관 | 높음 | 채용 공고·인턴십 |

## 해결 방식

- AI가 하는 일 (메모에 없음 — 아래는 기획 단계 제안, 팀 미논의):
  - 소상공인이 말이나 짧은 글로 "인스타 좀 해 주세요"처럼 요청하면 범위·산출물·기간이 정해진 퀘스트 명세로 바꾼다
  - 청년의 역량·관심과 퀘스트를 매칭하고 난이도 단계를 추천한다
  - 결과물 1차 검토와 피드백, 수행 이력을 포트폴리오로 자동 정리
- 사람이 하는 일: 의뢰자(소상공인·기업)가 결과물 최종 승인, 시가 소상공인 퀘스트 비용 일부 지원, 기업이 레벨 도달 청년 채용 검토

## 문턱 낮은 인터페이스

| 체크 | 항목 | 근거 |
| --- | --- | --- |
| [ ] | 앱 설치·회원가입 없이 첫 사용 가능 | 미정. 결제·정산 때문에 가입은 필요할 가능성 높음 |
| [ ] | 말(음성)·전화·문자처럼 이미 익숙한 채널로 사용 가능 | (제안) 소상공인이 말로 과제를 의뢰 |
| [ ] | 글을 잘 못 읽거나 화면이 작아도 쓸 수 있음 (큰 글씨·쉬운 말·스크린리더) | |
| [ ] | 핵심 결과까지 3단계 이내 | (제안) 소상공인: 말로 의뢰 → 퀘스트 확인 → 결과 승인 |
| [ ] | 막혔을 때 사람(창구·배움터·가족)에게 이어짐 | 디지털배움터 연계 가능성 (확인 필요) |

## 시민 체감 시나리오

|  | Before | After |
| --- | --- | --- |
| 상황 | 청년은 경력이 없어 지원조차 막힘. 가게는 SNS·메뉴판을 손대지 못함 | 청년은 실제 가게 과제를 수행하고, 가게는 시 지원으로 적은 비용에 결과물을 받음 |
| 걸리는 시간·단계 | 회의 미논의 | 퀘스트 1건 1~2주 |
| 결과 | 경력 공백 지속, 가게 홍보 부재 | 검증된 포트폴리오 누적 → 채용 연계. 가게는 홍보물·디지털 자산 확보 (수치 근거 없음) |

## MVP 범위

- 데모에서 보여줄 핵심 흐름 1개: (제안) 소상공인이 말로 의뢰 → AI가 퀘스트 카드로 정리 → 청년이 수락·제출 → 승인 후 경험치·포트폴리오에 반영
- 하지 않는 것: 실제 결제·정산, 시 지원금 집행, 실제 기업 채용 연동

- 연계 대상 (부서·기관·현장): 서울시 청년 일자리·소상공인 지원 부서, 디지털배움터(청년 수행자 교육 또는 소상공인 의뢰 지원) — 모두 확인 필요

## 리스크

| 리스크 | 대응 |
| --- | --- |
| 유료 과업의 노동법 문제 (근로자성, 최저임금, 플랫폼 노동) | 확인 필요 |
| 결과물 품질 편차, 분쟁 | 의뢰자 승인 + 단계별 난이도. 분쟁 처리 방식 미정 |
| 기존 프리랜서 마켓·공공 일경험 사업과의 차별성 | 유사 사업 조사 필요 — '검증된 경험치 → 채용 연계'와 '소상공인 비용 시 지원'이 차별점 후보 |
| 시 지원 재원과 지속성 | 확인 필요 |
| 정보 약자 문턱: 주 사용자인 청년은 디지털 역량이 높아 포용 가치가 약해 보일 수 있음 | 소상공인 의뢰 쪽 인터페이스를 말·쉬운 화면으로 낮추는 데 집중 |
| 6시간 해커톤에서 양면 플랫폼(의뢰자·수행자·검증·레벨) 구현 범위가 큼 | MVP는 의뢰 → 퀘스트 → 제출 → 승인 한 흐름만 |
