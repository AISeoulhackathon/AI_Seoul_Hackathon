# IDEA_14: 거꾸로 키오스크 — 배우지 말고, 비추세요

> 출처: 2026-11-03 세션 브레인스토밍에서 나온 후보를 `/ideate`로 정리했다. 사용자 인터뷰·구현·실증은 없다. 체크박스는 구현·검증 완료 여부이므로 모두 미체크이고, 시나리오의 단계 수는 설계 목표다. 같은 날 함께 검토한 'ARS 지름길'(AI 없이도 표로 해결돼 AI 핵심성 미흡)과 '대신 전화해드림'(AI 발신 고지·발신 API 확인 전 6시간 데모 불확실)은 카드로 만들지 않았다.

## 한 줄 요약

키오스크 앞에서 막힌 시민이 휴대폰 카메라로 화면을 비추고 원하는 것을 말하면, AI가 화면을 읽어 "지금 누를 버튼"을 사진 위에 표시하고 소리로 알려준다.

## 문제

- 누가, 어떤 상황에서, 무엇을 못 하는가: 식당·카페·병원·무인민원발급기 등에서 키오스크 화면 구성이 기계마다 달라, 고령자·저시력자 등은 뒤에 줄이 선 상태에서 다음에 무엇을 눌러야 할지 몰라 주문·접수를 포기하거나 남에게 부탁한다 (문제 가설, 현장 관찰·인터뷰로 검증 필요).
- 기존 접근의 한계 (추론): 키오스크 사용법 교육은 특정 기계 화면을 익히는 방식이라, 처음 보는 기계 앞에서는 다시 막힌다. 기계를 바꾸는 접근성 개선은 설치 주체(가게·기관)의 비용이 든다. 이 아이디어는 기계를 바꾸지 않고 시민 손에 있는 휴대폰으로 그 자리에서 돕는다.
- 근거: 기술 복잡도를 낮춰 고령자·장애인·소상공인 등 정보 약자도 복잡한 절차 없이 쓰는 문턱 낮은 인터페이스, 디지털 격차 해소([brief.md](../hackathon/brief.md) 추진 배경 2). ④ 자유과제는 시민 체감형 공익 가치와 포용적 AI 방향성을 반영해야 한다([공고·FAQ](../hackathon/announcement-faq.md#트랙문제-해석)).
- 확인 필요: 고령층 키오스크 이용 어려움에 관한 공식 통계(예: 디지털정보격차 실태조사 계열), 키오스크 접근성 관련 법·제도의 현재 의무 범위와 시행 시점. 출처 확인 전까지 수치·제도명을 쓰지 않는다 (`/research` 대상).

## 대상 사용자

| 사용자 | 디지털 역량 | 지금은 어떻게 해결하나 |
| --- | --- | --- |
| 고령자 | 전화·카메라·메신저는 쓰지만 처음 보는 화면 탐색은 어려움 (가설) | 직원·뒷사람·가족에게 부탁, 유인 계산대로 이동, 포기 (가설) |
| 저시력·지체장애인 | 개인차 큼. 화면이 높거나 글씨가 작아 읽기 어려움 가능 | 동행인 도움, 직원 호출 (가설) |
| 한국어가 익숙하지 않은 시민 | 기기 사용은 가능하나 메뉴 문구 이해 어려움 가능 | 번역 앱으로 화면 촬영 후 해석, 그림으로 추측 (가설) |
| 디지털배움터 강사 | 높음 | 기계별 화면을 교안으로 만들어 교육 (가설) |

## 해결 방식

- AI가 하는 일: 사진 속 키오스크 화면의 버튼·문구·현재 단계를 인식한다. 사용자가 말한 목표("아이스 아메리카노 한 잔 포장")와 화면을 비교해 다음에 누를 버튼 하나를 고른다. 사진 위에 큰 동그라미로 표시하고 쉬운 말로 읽어준다. 화면이 바뀌면 다시 비추게 해 단계마다 안내한다. 결제·개인정보 입력 단계에서는 직접 판단을 대신하지 않고 "여기서부터는 카드를 꽂으세요/직원에게 물어보세요"처럼 멈춘다.
- 사람이 하는 일 (담당자·가족·배움터 강사 등): 시민이 직접 버튼을 누른다(AI는 기계를 조작하지 않는다). 막히면 화면에서 "직원 부르기 문장"을 크게 띄워 보여준다. 디지털배움터 강사는 교육 시간에 이 도구로 "처음 보는 기계에서도 혼자 하는 법"을 연습시키고 오안내 사례를 모아 피드백한다.

| | Before | After |
| --- | --- | --- |
| 상황 | 혼자 간 카페 키오스크에서 메뉴 화면은 찾았지만 온도·크기·포장 선택에서 멈춘다. 뒤에 줄이 생긴다. | "아이스 아메리카노 한 잔 포장"이라고 말하고 화면을 비추면 다음 버튼에 동그라미가 뜨고 소리로 안내된다. |

| 결과 | 주문 포기 또는 남의 도움에 의존 (가설) | 결제 직전까지 스스로 진행하고, 결제는 본인이 직접 (목표) |

## MVP 범위

- 데모에서 보여줄 핵심 흐름 1개: 팀이 만든 모의 카페 키오스크 화면(태블릿·노트북) 앞에서, 휴대폰 웹으로 "아이스 아메리카노 한 잔 포장"을 말한다 → 화면 촬영 → 누를 버튼에 동그라미 + 음성 안내 → 눌러서 화면이 바뀌면 다시 촬영 → 결제 화면에서 멈추고 "카드를 꽂으세요" 안내.
- 하지 않는 것: 실시간 영상 위 AR 추적(사진 한 장 단위로 안내), 키오스크 직접 조작·결제 대행, 모든 업종·기계 지원, 외국어 안내(확장 후보), 실제 매장 키오스크 시연(촬영 허락 미확인).
- 범위 전제: 6시간 현장 개발 기준 제안이다. 모의 키오스크 화면의 디자인·와이어프레임은 사전 준비 허용 범위(디자인)에 해당하지만, 화면 인식·버튼 판단·안내 로직은 핵심 기능이므로 본선 현장에서만 구현한다([CLAUDE.md §2-5](../../CLAUDE.md#2-5-대회-준비구현-경계)).
- 검증 지표(제안): 첫 시도에서 맞는 버튼을 가리킨 비율, 결제 직전까지 도달한 비율, 잘못된 버튼을 가리킨 횟수.

## 서울시 시정·디지털배움터 연계

- 연계 대상 (부서·기관·현장): 서울 AI 디지털배움터의 키오스크·스마트폰 활용 교육 현장, 키오스크를 쓰는 공공시설(무인민원발급기 등)과 골목상권 소상공인 매장 (모두 협의 전 제안)
- MVP 이후 운영 주체·방식: 배움터 강사가 교육 도구로 쓰고, 현장에서 나온 오안내 사례를 평가 세트로 모아 개선하는 구조를 제안한다. 매장 입구에 "키오스크 도우미" QR을 붙여 소상공인이 별도 비용 없이 손님 이탈을 줄이는 확장(② 소상공인 연계)도 후보다. 공식 운영 주체는 미정.
