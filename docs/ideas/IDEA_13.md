# IDEA_13: 서울 돌봄첫걸음 — 갑작스러운 돌봄 공백에서 상담까지

> 출처: 팀원 개인 기획 초안(2026-11-02, 원본 번호 IDEA_03 → 저장소 번호 IDEA_13). 사용자 인터뷰·구현·실증은 아직 없다. 체크박스는 구현·검증 완료 여부이므로 모두 미체크이고, 시나리오의 단계 수는 설계 목표다. 아래 외부 출처는 원 작성자가 수집한 링크로 이 저장소에서 재확인하지 않았으며 `RES_XX` 조사 카드로 아직 옮기지 않았다(`/research` 대상).

## 한 줄 요약

갑작스러운 돌봄 공백을 겪는 시민과 가족의 상황을 AI가 정리해 관련 서비스 종류를 설명하고 공식 상담을 시작하도록 돕는다.

## 문제

- 퇴원·돌봄자 부재 등으로 일상생활 지원이 필요한 시민과 가족이 어디에 어떤 정보를 전달해야 하는지 모른다 (문제 가설, 인터뷰로 검증 필요).
- 근거: 정보 약자가 갑작스러운 돌봄 공백에 노출되고, 대도시형 복합 돌봄 수요가 늘고 있다([brief.md](../hackathon/brief.md) 트랙 ①).
- 근거: [서울 돌봄SOS 대상 기준(서울복지포털)](https://wis.seoul.go.kr/wfs/sos/service.do)은 일상생활 어려움·돌봄자 부재·기존 서비스 공백 등의 조건과 당사자·가족·발견자의 연락 경로를 명시한다.
- 근거: [서울시복지재단 돌봄SOS](https://welfare.seoul.kr/web/contents/business1-3-7.do)는 주민센터 신청, 현장확인, 돌봄계획 수립 절차를 설명한다.
- 선례: [GetCalFresh(Code for America)](https://codeforamerica.org/news/california-launches-code-for-americas-getcalfresh-in-all-58-counties/)의 신청 지원 방식과 [뉴저지 주정부 행정 AI 번역](https://www.nj.gov/labor/lwdhome/press/2024/20241205_aitransition.shtml)의 쉬운 표현·검수 원칙을 응용한다. 같은 돌봄 AI의 검증된 성과를 주장하지 않는다.

## 대상 사용자

| 사용자 | 디지털 역량 | 지금은 어떻게 해결하나 |
| --- | --- | --- |
| 일상생활에 도움이 필요한 시민 | 개인차 큼; 긴 입력이 어려울 수 있음 | 동주민센터·가족에 도움 요청 (공식 경로 및 가설) |
| 가족·가족돌봄청년 | 기기 사용 가능해도 제도 경험 부족 가능 | 기관에 전화하며 상황 설명 (가설) |
| 주변의 도움 제공자 | 간단한 모바일 입력 가능 수준 가정 | 당사자 동의와 필요를 확인하고 상담 안내 (검증 필요) |

## 해결 방식

- AI가 하는 일: 누가·언제부터·어떤 일상생활에 도움이 필요한지 정리하고, 공식 지침의 서비스 종류와 연결한다. 상담 요약과 확인 질문을 생성하되 적격 여부와 서비스 제공을 확정하지 않는다.
- 사람이 하는 일 (담당자·가족·배움터 강사 등): 이용자가 요약을 수정·확인하고 직접 연락한다. 돌봄 담당자가 실제 상황·적격성을 확인하고 계획을 수립한다. 가족·강사는 동의 아래 입력을 돕는다.

## 문턱 낮은 인터페이스

| 체크 | 항목 | 근거 |
| --- | --- | --- |
| [ ] | 앱 설치·회원가입 없이 첫 사용 가능 | 설치·가입 없는 모바일 웹; 본인/가족 상황 선택 |
| [ ] | 말(음성)·전화·문자처럼 이미 익숙한 채널로 사용 가능 | 짧은 선택형 입력과 전화 버튼; 음성 입력은 후속 후보 |
| [ ] | 글을 잘 못 읽거나 화면이 작아도 쓸 수 있음 (큰 글씨·쉬운 말·스크린리더) | 큰 버튼·한 화면 한 질문·쉬운 말; 스크린리더 테스트 필요 |
| [ ] | 핵심 결과까지 3단계 이내 | 상황 입력 → 추가 확인 → 상담 카드의 3개 주요 화면 목표 |
| [ ] | 막혔을 때 사람(창구·배움터·가족)에게 이어짐 | 공식 주민센터 상담 경로로 연결; 즉시 통화·상담 완료 여부는 보장하지 않음 |

## 시민 체감 시나리오

| | Before | After |
| --- | --- | --- |
| 상황 | 퇴원한 가족이 식사를 챙기기 어렵지만 낮에 돌봐줄 사람이 없다. | 필요한 도움과 돌봄 공백을 정리하고 공식 상담 경로를 확인한다. |
| 걸리는 시간·단계 | 제도 검색·연락처 탐색·상황 재설명; 시간 미측정 | 3개 주요 화면에서 상담 준비 목표; 실제 서비스 이용 단계는 별도 |
| 결과 | 서비스 종류와 문의 내용을 확신하기 어려움 (가설) | 시민이 검토한 상담 요약·질문·공식 연락 경로 확보 |

## MVP 범위

- 데모에서 보여줄 핵심 흐름 1개: 한 자치구의 퇴원 후 돌봄 상황 입력 → 식사·일상생활 필요 확인 → 상담 요약과 공식 전화 버튼.
- 하지 않는 것: 의학적 진단, 응급도 자동 판정, 서비스 적격성 확정, 실시간 제공기관 배정, 자동 전화·예약. 상태 표시는 사용자 직접 기록만.
- 범위 전제: 6시간 당일 개발에 맞춘 제안이다. 사전 코드·데이터 준비 허용 범위는 미확인([work-plan.md](../planning/work-plan.md) 미결정).
- 검증 지표(제안): 상담 준비 시간, 상담 요약의 정보 누락, 다음 단계 이해도.

## 서울시 시정·디지털배움터 연계

- 연계 대상 (부서·기관·현장): 동주민센터 돌봄 담당자, 서울시복지재단 돌봄SOS, 디지털배움터의 시민 사용 지원 (협의 전 제안)
- MVP 이후 운영 주체·방식: 서비스 안내·연락처는 운영팀이 정기 확인하고 담당자가 변경 사항을 검토하는 구조를 제안한다. 연계 협약·운영 인력·예산은 미확정.
