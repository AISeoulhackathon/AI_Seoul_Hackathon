# IDEA_09: AI 정기 안부 대화와 돌봄 모니터링

> 출처: [1차 회의](../note/20261102-ideation-meeting-1.md), [회의 후 확장 메모](../note/20261102-idea09-expansion.md)

## 한 줄 요약

정해진 시간에 AI가 먼저 말을 걸어 자연스럽게 안부를 묻고 필요한 복지 정보·일정을 알려 주며, 일정 횟수 이상 응답이 없거나 위험 신호가 보이면 담당자에게 알린다.

확장안(돌봄 레이더 콜): 대화 속 위험 신호를 점수로 누적하고, 임계치를 넘으면 해당 구 제도를 음성으로 안내해 신청까지 잇는다. 신청주의(본인이 찾아 신청해야 받는 구조)를 뒤집는 것이 핵심이다.

## 문제

- 담당자 한 명이 많은 대상자를 맡아 직접 찾아가기 어렵다 (회의 중 '1명당 최대 1,000명' 언급 — 확인 필요). 고독사 위험군을 놓친다.
- 정보 약자는 제도를 스스로 찾아 신청하지 않는다(회의에서 [IDEA_07](IDEA_07.md)의 딜레마로 지적). 위험이 보여도 제도까지 이어지지 않는다.
- 근거: 복지 트랙 돌봄 수요·사각지대([brief.md](../hackathon/brief.md)).

## 대상 사용자

| 사용자 | 디지털 역량 | 지금은 어떻게 해결하나 |
| --- | --- | --- |
| 홀몸어르신 | 낮음 | 담당자 방문·전화 |
| 장애인 | 낮음~중간 | 복지센터 방문·대리 |
| 1인가구(고립 청년 포함) | 높음 (단, 스스로 도움을 청하지 않음) | 회의 미논의 |
| 동주민센터 복지 담당자 | 중간 | 수작업 관리 |

## 해결 방식

- AI가 하는 일: 정기 음성 대화, 대화 기반 심리 상태 분석, 최신 복지 정보 안내, 무응답·위험 감지
  - (확장) 대화에서 위험 지표 추출·누적: 끼니 거름, 외출 감소, 통증·불면 언급, 말수 감소
  - (확장) 점수가 임계치를 넘으면 거주 자치구 제도를 매칭해 음성으로 안내, 신청 대행 연결
- 사람이 하는 일: 담당자 — 알림 받고 방문·연락. 고위험이면 즉시 알림을 받는다

```text
정기 안부 통화 ─▶ 위험 지표 누적 ─┬─ 임계치 초과 ─▶ 구 제도 음성 안내 ─▶ 신청 대행 연결
                                  ├─ 고위험       ─▶ 동주민센터 담당자 즉시 알림
                                  └─ 무응답 반복   ─▶ 담당자 알림 ─▶ 방문
```

## 문턱 낮은 인터페이스

| 체크 | 항목 | 근거 |
| --- | --- | --- |
| [ ] | 앱 설치·회원가입 없이 첫 사용 가능 | 확장안은 AI가 집 전화로 먼저 걸므로 스마트폰·앱 불필요. MVP는 앱 내 음성이라 미정 |
| [ ] | 말(음성)·전화·문자처럼 이미 익숙한 채널로 사용 가능 | 음성 대화, 집 전화 |
| [ ] | 글을 잘 못 읽거나 화면이 작아도 쓸 수 있음 (큰 글씨·쉬운 말·스크린리더) |  |
| [ ] | 핵심 결과까지 3단계 이내 | 전화를 받아 말만 하면 됨. 제도 신청은 대행 연결 |
| [ ] | 막혔을 때 사람(창구·배움터·가족)에게 이어짐 | 담당자 알림 |

## MVP 범위

- 데모에서 보여줄 핵심 흐름 1개: AI 안부 대화(앱 내 음성) + 무응답 시 담당자 화면 알림
- 하지 않는 것: 실제 전화망 발신
