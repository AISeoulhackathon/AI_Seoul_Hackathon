## 트랙·문제 해석

| 트랙 | 주제 | 슬로건 |
| --- | --- | --- |
| ① | 복지·돌봄 사각지대 해결 | 돌봄과 복지가 필요한 사람을 놓치지 않는 서울 |
| ② | 소상공인 경영 문제 해결 | 지속 가능한 가게를 만드는 서울 |
| ③ | 청년 일자리·직무 미스매칭 문제 해결 | 일할 기회를 연결하는 서울 |
| ④ | [자유주제] 서울시민의 삶을 바꾸는 AX 자유 과제 (공익 서비스) | 당신의 아이디어로 만드는 더 나은 서울 |

FAQ는 ①~③을 "트랙 1, 2, 3", ④를 "주제 4번 '자유과제'"로 부른다. 트랙별 문제 근거 수치는 [brief.md](brief.md#트랙)에 있다.

- ①~③의 슬로건과 제시 근거는 문제 당위성을 돕는 자료다. 그대로 따를 필요 없이 세부 페인포인트를 구체화하거나 다각도로 해석해도 된다.
- ④는 ①~③ 영역 밖에서 교통·환경·안전 등 서울의 문제를 정의하고 시민 체감형 공익 가치와 디지털배움터의 포용적 AI 방향성을 반영해야 한다.

주요 평가 요소는 현장에서 실제 작동하는 **실용성**, 정보 약자도 쉽게 쓰는 **디지털 포용 UX**, **시민이 체감할 수 있는 효과**다. 세부 배점·제출 경로·마감 시각·발표 시간은 공유본에 없다.

## 사전 준비 허용 범위

**핵심 기능 개발(코딩)은 본선 당일 현장에서 진행한다. commit 기록을 확인하며 사전 개발 적발 시 실격한다.** AI 코딩 도구 사용 허용이 사전 핵심 기능 작성 허용을 의미하지 않는다.

| 허용 항목 | 범위 |
| --- | --- |
| 기획 | 문제 정의, 기능 기획, 사용자 시나리오, 발표자료 구성 |
| 디자인 | 와이어프레임, UI·화면 설계, 로고 |
| 개발 환경 | 계정 생성, GitHub 저장소, 배포 환경 구성, 프레임워크·라이브러리 설치 |
| 개발 계획 문서 | ERD, 파이프라인 등 |
| 기본 템플릿 | 빈 프로젝트 초기 구조·스캐폴딩, 공개 오픈소스·공개 API 활용. 주제를 해결하는 핵심 기능 코드는 당일 구현 |

FAQ는 시작 시 사전 제출 작업물 피드백을 참고하도록 안내한다. 사전 제출 대상·기한·방법은 공유본만으로 알 수 없어 확인 필요다.
